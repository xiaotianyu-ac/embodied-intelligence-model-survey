## 数据与评测：如何判断模型真的进步

### 数据资产的贡献与边界

| 数据或接口 | 核验的代表规模/特征 | 对模型的意义 |
|---|---|---|
| Open X-Embodiment | 原论文22种机器人，统一数据表示 | 验证跨本体共享；各模型实际混合子集不同 [R001] |
| BridgeData V2 | 60,096条轨迹、24个环境；包含遥操作和脚本运行 | 物体与场景多样性；与OXE存在包含关系 [R021] |
| DROID | 76k条轨迹、350小时、564场景 | 分散真实环境采集；须注意标定与数据修订 [R002] |
| RoboMIND | 原论文107k条、479任务、96类物体 | 统一采集平台上的多本体数据 [R004] |
| AgiBot World | Beta公布1,003,672条轨迹 | 双臂操作规模化；机器人实例数不等于本体种数 [R005] |
| UMI / DexUMI | 手持夹爪或人手接口，强调可迁移示范 | 降低采集约束，同时仍需时序、姿态与可达性对齐 [R003][R020] |
| RoboCasa365 | 365任务、2500+厨房；600+小时人工与1600+小时合成示范 | 系统化组合与场景覆盖；示范小时不能都算真机小时 [R022][R027] |

这些规模不能相加得到“独立具身数据总量”：同一轨迹可被多个集合与训练混合重复使用；帧、步骤、片段、轨迹与小时是不同单位。人类视频擅长提供物体、任务与运动先验，却通常缺少执行器命令和触觉；真机轨迹具有动作落地价值，但覆盖成本高；仿真便于生成奖励与危险情形，仍受接触和传感器差距制约。数据价值应按覆盖的场景、本体、技能、失败恢复和传感模态分解。

LeRobot提供数据与机器人接口，Isaac Lab、ManiSkill等提供学习和仿真工具。这些基础设施使不同模型更易比较，但统一容器格式不等于统一控制语义。关节顺序、旋转约定、归一化、时间戳、相机标定和控制周期仍须逐项对齐。[R011][R013][R014]

### 不同基准回答不同问题

| 基准 | 主要测量对象 | 比较前必须固定 |
|---|---|---|
| LIBERO | 语言操作、对象/空间/目标与迁移 | 套件、数据预处理、演示量、初始状态、rollout长度 [R007] |
| CALVIN | 连续语言子任务链 | ABC-D等环境划分；平均完成链长不能当成功百分比 [R008] |
| SIMPLER | 特定真机设置的仿真代理评估 | Visual Matching和Variant Aggregation、机器人与控制频率 [R009] |
| RoboTwin 2.0 | 双臂操作、随机化与本体差异 | clean/randomized设置、任务和动作接口 [R010] |
| RMBench | 依赖历史信息的操作 | 记忆任务划分、历史长度、检查点版本；2026有重训权重 [R023] |
| RoboCasa365 | 厨房组合技能与环境泛化 | 版本、任务层级与时间限制；2026年5月任务horizon增加1.5倍 [R022] |
| BEHAVIOR-1K | 长程家庭活动与交互状态 | 具体挑战赛子集、观测限制、超时和本体；不是全1000任务统一已解决 [R012][R028] |
| MolmoSpaces | 多设置模型比较与场景扩展 | 数据来源、动作空间、覆盖任务、是否微调及测试日期 [R019] |

这解释了为什么本综述不提供一个“所有模型总排行榜”。高LIBERO成功率可能来自任务专项训练，较低的零样本跨场景分数反而测量更困难的问题；二者不能直接宣布优劣。模型更新还可能伴随更长horizon、更多采样或更高分辨率。至少应同时列出训练数据、是否见过任务/物体/场景/本体、模型版本、执行周期、推理预算和评测次数。

### 建议的统一验收设计

以下是研究与工程建议，不是本仓库已经执行的实验。建立四级测试：同分布技能；新物体/视角/语言；新场景与组合任务；新本体及长程自主运行。每级都包含扰动、遮挡、抓取失败和恢复情形，避免仅测试顺利路径。训练、验证、测试按场景和采集批次隔离，并报告预训练数据中的潜在重叠。

第一组基线固定动作接口与数据量，比较ACT/DP、可微调VLA和加入结构化规划的系统。第二组保持同一骨干，比较单步/动作块、离散/流生成、视觉/视觉加本体或触觉、同步/异步、记忆开/关。第三组对世界模型比较“无搜索、固定计算搜索、增加计算搜索”，分别报告模型能力与预算收益。对商业模型，无法控制训练数据时只做系统验收，不把差异解释成架构因果结论。

报告指标至少包含：任务成功和完整链成功；完成时间；人工干预每小时；恢复率；碰撞、掉落与急停；视觉到动作时延的中位数和尾部；单位任务能耗；数据采集与适配成本。每个任务与条件预先定义重复次数，并给出置信区间；按任务和场景分层统计，避免把同一场景的相关片段当成独立样本。全部尝试都进入日志，失败与超时不能剪辑消失。

## 模型关系的综合论述

### 关系不是单一谱系

本文将关系分为五类：**明确初始化/复用、同系列版本演进、方法组合、系统互补、本文分析比较**。只有原论文或官方实现明确说明时，才使用“继承权重”“在某模型上后训练”等表述。两个模型都使用Transformer或流匹配，仅能说明共享范式。附属关系数据记录每条边的证据来源与性质，读者可以检查图中箭头代表什么。

第一条关系是**从专用模仿到通用条件策略**。ACT与DP主要解决动作序列与多峰控制；RT系列、Octo与OpenVLA把任务与本体覆盖放到中心。后者并不让前者失效：数据较少、任务固定、算力受限时，紧凑行为克隆仍是有价值的基线；大VLA也经常采用动作块与生成头。在同等任务数据上比较，才能判断互联网预训练带来多少额外收益。

第二条关系是**语言语义与动作分布的分工逐步显式化**。RT-2将动作映射到语言式token空间，OpenVLA提供开放的迁移路线；PI、GR00T、MolmoAct2与小米等使用连续动作专家缓解细粒度控制与长动作序列的负担。FAST改变动作编码，OFT改变适配与动作输出配方，异步执行改变调度。这三个方向分别作用于表示、训练与运行时，不应简单排成前后代。

第三条关系是**三维几何与大规模预训练互补**。PerAct/RVT侧重让观测与动作共享空间结构，3D Diffuser Actor进一步结合生成动作。大VLM擅长语义迁移，但不会自动保证毫米级坐标、正确碰撞边界或接触状态。几何模块可以成为可检查接口，也可能增加标定与计算成本；是否融合应由空间误差来源决定。

第四条关系是**世界模型与VLA正在靠近，但职责仍不同**。GR-1/GR-2把未来预测纳入动作学习；GO-1用潜动作作中间计划；Cosmos Policy把视频基础模型适配为动作、未来和值的联合建模；JEPA-AC用潜空间行动后果支持搜索。它们提供四种不同连接方式：辅助监督、中间表示、统一生成、显式规划。只有当推理真的比较行动后果时，才应称其在部署时使用世界模型规划。[R005][R006][W020][W021][W028][W035][W023][W025][W026]

第五条关系是**高层通用智能与低层全身控制的接口融合**。HumanPlus、SONIC与Helix说明高层语义、动作目标和稳定执行可以工作在不同时间尺度。让VLA输出全身关节向量不等于已经解决平衡、接触与扰动恢复；让低层模型能稳定行走也不等于具备开放任务理解。接口必须携带目标坐标、时序、约束和失败反馈。

第六条关系是**模仿、反馈后训练与在线学习逐渐形成循环**。PI的经验学习方向与HIL-SERL分别展示通用预训练后优化和限定任务反馈优化的路径。两者共享利用实际结果改进策略的目标，但奖励、数据规模、可部署权重与安全边界不同，不能互换实验结论。世界模型可以降低真实探索成本，同时也会引入可被策略利用的模型偏差。[R015][R016]

### 六组有助于选型的直接对照

| 对照 | 真正差异 | 应做的验证 |
|---|---|---|
| ACT vs DP | 潜变量动作块与去噪动作分布；模型/数据规模可独立改变 | 同演示量、同反馈周期的精度、失败率与时延 |
| OpenVLA vs OFT | 可复用骨干下的适配与动作输出配方变化 | 同骨干、同训练预算，而非只看名字 |
| pi系列 vs GR00T系列 | 类似连续动作专家范式，不同骨干、混合数据、本体接口和版本目标 | 固定权重版本与数据许可，测本体适配成本 |
| V-JEPA-AC vs视频世界模型 | 紧凑潜空间后果预测 vs可观看未来；都可能用于规划 | 同搜索时间、动作候选数和真实成功 |
| 语义规划器＋技能 vs端到端VLA | 显式可检查子目标 vs联合学习的动作接口 | 新组合、失败恢复、计划落地与模块开销 |
| Helix/SONIC全身层级 vs仅机械臂VLA | 平衡与接触频率、全身动作接口和低层稳定性 | 行走中操作、扰动和多接触任务，而非静止桌面成绩 |

## 工程架构与开放程度

建议将实际系统分为数据与标定、状态与历史、任务规划、动作生成、控制与安全边界、反馈记录六个接口。慢速语义推理可在服务器执行，动作专家在近端加速器运行，伺服与急停留在确定性控制路径。具体频率由硬件、任务和延迟测量决定，不根据营销中的System 1/System 2命名自行假定。生产闭环应知道当前动作基于哪一帧、哪个模型和哪个归一化版本。

开放程度至少分五项检查：论文机制、推理代码、权重、训练代码与配方、实际训练数据。再单列许可证与商业使用限制。一个模型有GitHub并不等于五项均完整；模型卡列出部署硬件也不等于所有模式都达到实时。公开数据和分阶段检查点有助复现，但标定、控制器与失败处理仍可能依赖团队经验。[R013][R014][R017]

工程选型宜从任务约束出发。固定、精细、演示可收集的工作站可先比较ACT/DP与HIL-SERL；需要语言泛化和多任务共享时比较开源VLA；存在明确空间约束时引入几何规划；需要选择不同后果时评估世界模型搜索；涉及行走与操作时先验证低层全身稳定性，再接入通用语义。这里是基于模型机制的选型建议，不是采购排名或部署保证。

## 五个未来技术挑战

### 挑战一：可迁移的动作与接触表示

跨本体共享视觉和语言比共享执行器语义容易。不同关节、夹爪、手部、控制频率和力反馈使同一任务对应不同动作分布；人类视频还缺少真实控制标签。值得研究将本体约束、几何目标与接触状态显式编码，并在共享策略之下配置适配层。验收指标应包含新本体所需示范量、接触力误差、插接成功、约束违例和迁移后的稳定性，不能只测原本体成功率。

### 挑战二：长期记忆、可验证计划与失败恢复

真实任务需要记住被遮挡物体、已经完成的步骤和曾失败的策略。堆叠更多视频帧可能提高成本，也可能记住无关背景；文字计划可能与实际状态脱节。可研究事件级记忆、对象状态图、显式完成判据和带恢复分支的计划，将当前感知与长期状态区分。使用RMBench和长程基准作为部分测试入口，并增加真实遮挡、重新摆放与中断恢复；报告完整任务链成功率、恢复时间和错误记忆持续时间。[R023][R012]

### 挑战三：可用于行动决策的世界模型

世界模型可能生成视觉上合理、控制上错误的未来，尤其在接触、可变形物体、遮挡和其他主体互动中。规划越长，误差越可能被策略放大；更大搜索预算也可能只是更有效地寻找模型漏洞。研究重点应包括行动条件校准、不确定性、物理约束和真实反馈校正。验收需要反事实动作辨别、预测与真实任务结果的一致性、固定预算的规划增益，以及异常情况下的保守退回行为。

### 挑战四：实时性、能耗与控制可靠性联合优化

大型视觉语言骨干、长历史与迭代动作生成争夺端侧计算资源；异步缓冲又改变反馈时效。值得将量化、蒸馏、KV复用、动作块调度和控制稳定性一起设计，并在扰动下测试动作衔接。验收指标应包含尾部时延、观测年龄、动作连续性、每任务能耗和故障恢复，而不是只测离线吞吐。小米异步训练案例说明训练条件与部署调度需要共同考虑。[R024][R025]

### 挑战五：从演示成绩到可审计的持续学习

从成功视频筛选数据、只报告最佳checkpoint、隐藏人工接管，会高估实际能力。持续学习又会带来奖励错配、遗忘、数据泄漏和版本回退问题。研究与工程应保留所有尝试、干预和失败，建立独立场景测试与可回滚的模型发布过程；同时明确人类视频、场景资产、权重与训练数据的许可。验收应追踪跨版本回归、任务成功置信区间、人工分钟和长期干预频率，才能判断系统是否真正减少人类负担。[R015][R019][R022]

## 阅读与复现路线

理解方法可依次阅读ACT/DP的动作学习，SayCan/PaLM-E的语义落地，RT/OpenVLA的预训练迁移，PI/GR00T的连续动作专家，PerAct/RVT的几何接口，再读JEPA/Cosmos与全身控制。复现实验宜从固定机械臂、清晰动作接口和少数可重复任务起步，随后增加域外变化与恢复情形；不要同时更换本体、传感器、数据和模型后再解释单个因素。

本仓库保留模型卡、关系边、数据与基准表、产品矩阵、证据与不确定性记录、双语报告以及构建与验证脚本。它提供研究资料和可执行的评测设计，不包含已经复现的模型训练结果，也不分发第三方论文全文、模型权重或原始机器人数据。后续更新应在同一来源台账中记录版本变化，并重新核对图、表和正文的一致性。
